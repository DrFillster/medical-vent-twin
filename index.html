ARDS Clinical Twin v0.6

A browser-based persistent ARDS clinical twin for interactive mechanical-ventilation education — software development and computational-verification report.

EDUCATIONAL / RESEARCH SIMULATION · SYNTHETIC PATIENT · NOT CLINICALLY VALIDATED · NOT FOR PATIENT CARE

The v0.6 release extends earlier browser Vent builds into a persistent synthetic-patient environment: a single synthetic aspiration-ARDS teaching phenotype that survives repeated ventilator changes, mechanics maneuvers, holds, and time advances on one shared timeline. Recruitment history, intervention log, mechanical state, and gas-exchange / hemodynamic state remain associated with the same patient rather than resetting between experiments.

Run v0.6 in browser

  • Open the v0.6 Clinical Twin — one-click reference aspiration-ARDS teaching patient that persists across settings and time advances.
  • One patient, one timeline — after initialization, ventilator and recruitment changes do not create a new patient. Pre/post-intervention physiology can be compared on a common patient clock.
  • Ventilator controls — mode (VC-AC, PC-AC), PEEP, FiO2, respiratory rate, tidal volume or inspiratory pressure, inspiratory flow, inspiratory pause, inspiratory time.
  • Mechanics maneuvers — inspiratory and expiratory holds, passive-mechanics derivation (plateau pressure, total and intrinsic PEEP, driving pressure).
  • Synchronized cardiopulmonary outputs — PaO2, PaCO2, pH, heart rate, mean arterial pressure, cardiac output alongside 3-compartment lung state.
  • Display — pH formatted to exactly 2 decimal places; PaO2, PaCO2, MAP as whole numbers; pressure / flow / volume waveforms; per-variable physiologic trends aligned to the patient clock with intervention markers.
  • Continuous-run / pause / resume — patient time advances at 1× bedside pacing (no fast-forward / catch-up), pause freezes the patient clock and preserves state, resume continues without resetting.
  • Session export — JSON record of the clinical session includes the intervention timeline and the per-variable physiology trend for inspection or downstream analysis.

What v0.6 is — and what it is not

  • Educational / research simulator — the reference case is a synthetic aspiration-ARDS teaching phenotype, not a deidentified clinical record or patient-specific model.
  • No native HumMod executable is bundled — the browser product routes through a reduced, source-aligned HumMod-derived cardiopulmonary model; the native HumMod runtime remains a separate research workbench.
  • No production server, no clinical data feed, no patient-record integration — the deployable is a static browser application served over HTTPS.
  • Not clinically validated — passing computational verification establishes software behavior according to encoded contracts in tested scenarios; it does not validate prediction of an individual patient, expert performance, or learner outcomes.
  • Not a treatment recommender — ventilator changes are simulation inputs, not clinical recommendations.

Deployment model

  • Cloudflare static HTTPS serving the same ards-twin-v0.5-progress/web/ tree from this repository — no GitHub Actions, no server API, no native HumMod executable, no patient data.
  • CI is intentionally manual-only on the vent repo (no push / pull-request routine runs).
  • Deployment commit: 0a821e9 on main, with 4e705d6 as the v0.6 product commit the live-deploy packet anchors against. Each runtime file (app.js, engine.js, clinical-worker.js, worker.js, clinical-cases.json, index.html, styles.css) is served straight from the working tree of the launchd-managed origin at 127.0.0.1:8770.
